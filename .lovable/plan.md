
## ความคิดเห็น

เห็นด้วย 100% — UX ปัจจุบันบังคับให้ User เข้าใจคอนเซปต์ "rule vs KB" ก่อนถึงจะใส่ถูก = ผิดทิศ. ทางแก้คือ **ให้ AI เป็นคนตัดสิน** User แค่พิมพ์สิ่งที่อยากสอน → AI จัดเข้าที่ถูกให้

## ดีไซน์ใหม่: "พิมพ์สอน" (Smart Teach Box)

### Bonus: รับ paste ก้อนใหญ่
User paste โน้ตยาวๆ (เช่น "ค่าส่ง... การชิม... โปร...") → AI **แตกเป็นหลายข้อ** → แสดง list preview ให้ติ๊กเลือก save ทีละข้อ/ทั้งหมด

### List view เดิมยังอยู่
ใต้ Smart Box ยังเห็นรายการกฎ + KB ที่มี เพื่อแก้/ลบรายตัว (เผื่อ user อยากจัดเอง)

## เกณฑ์ที่ AI Classifier ใช้

System prompt ของ classifier (กระชับ):
1. **กฎ** ถ้า: ห้าม/ต้อง/อย่า/วิธีคุย/รูปแบบตอบ/trigger ที่ต้องตื่นตัวแม้ลูกค้าไม่ถาม
2. **KB** ถ้า: มีตัวเลข/ราคา/รายการ/ข้อมูลตอบเมื่อถูกถาม/FAQ
3. **ก้ำกึ่ง** เช่น "ต่างจังหวัดต้องบวกค่าส่ง" → ตัดสินใจ + อธิบายเหตุผล (1-2 บรรทัด) ให้ User ดูได้
4. ถ้าเป็น KB → propose title + category (เลือกจาก existing categories ก่อน, ใหม่ถ้าจำเป็น)
5. ถ้าเป็นกฎ → refine ให้สั้น ชัด, action-oriented
6. เช็ค similar existing → ป้องกัน duplicate

ใช้ Lovable AI `google/gemini-2.5-flash` — เร็ว ถูก เหมาะกับงาน classify

## ผลลัพธ์ตาม Goals

| Goal | ทำได้ยังไง |
|---|---|
| **UX ง่ายต่อคนไม่รู้ AI** | กล่องเดียว พิมพ์แล้วจบ — เหมือนคุยกับเลขา |
| **ประหยัด token ปลายทาง** | KB ยัง on-demand เหมือนเดิม / กฎยังเป็น always แต่ classifier กรองให้ใส่แค่ที่จำเป็นจริงๆ + dedupe |
| **ผิดพลาดน้อยที่สุด** | AI refine ข้อความให้ชัด + กัน duplicate + แสดงเหตุผลให้ user ตรวจก่อน save |
| **เปลี่ยนใจได้** | ปุ่ม "AI จัดผิด → ย้ายอีกฝั่ง" 1 คลิก |

## รายละเอียดทางเทคนิค

**Edge function ใหม่:** `classify-knowledge`
- Input: `{ text, existing_rules: string[], existing_kb_titles: string[], categories: string[] }`
- Output:
  ```json
  {
    "items": [{
      "type": "rule" | "knowledge",
      "title": "...",       // ถ้า knowledge
      "category": "...",     // ถ้า knowledge (เลือกจาก existing หรือ "__new__:ชื่อใหม่")
      "content": "...",      // ข้อความสุดท้ายที่จะ save
      "reasoning": "เหตุผลสั้นๆ 1-2 บรรทัด",
      "similar": [{ "type":"rule","snippet":"...","id":"..." }]
    }]
  }
  ```
- ใช้ `google/gemini-2.5-flash` ผ่าน Lovable AI Gateway (มี `LOVABLE_API_KEY` แล้ว)
- System prompt 200-300 token, output JSON เล็ก — ค่าใช้จ่าย ~0.001$/ครั้ง

**Component ใหม่:** `src/components/knowledge/SmartTeachBox.tsx`
- Input + button + preview card(s)
- Hook: `useMutation` invoke `classify-knowledge`
- บันทึก → insert ตรงเข้า `app_settings.strict_rules` หรือ `knowledge_base` ตามผล

**ปรับ:**
- `src/pages/Knowledge.tsx` → ใส่ `<SmartTeachBox/>` บนสุดของหน้า (เหนือ tabs เดิม)
- หน้า Settings → "กฎ AI" ยังเก็บไว้ (list view สำหรับแก้/ลบ) แต่เพิ่มลิงก์ "💡 เพิ่มแบบ Smart → ไปหน้าสอน AI"
- ไม่ต้องแก้ prompt-builder / edge functions อื่น — ปลายทางเหมือนเดิม

## Phase

1. **Phase 1 (ขอทำเลย):** Edge function classifier + SmartTeachBox component + วางในหน้า Knowledge
2. **Phase 2 (ถ้าชอบ):** Bulk paste → แตกหลายข้อ + List view ของรายการที่ classifier ทำไว้แล้ว
3. **Phase 3:** Auto-suggest จาก conversation — สแกนแชทจริงทุก N วัน → เสนอ "ลูกค้าถามคำนี้บ่อย ยังไม่มีคำตอบใน KB อยากเพิ่มไหม?"
