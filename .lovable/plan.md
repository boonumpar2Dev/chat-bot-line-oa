## งานที่จะทำ

### 1. ปรับฟอร์ม Pricing Tier (`src/pages/Knowledge.tsx`)
ปัจจุบันมีแค่ `tier_name | guest_count | price` — เพิ่มฟิลด์ให้กรอก "พระ/แขก" แยกได้ (edge function รองรับ `total_pax/monk_pax/guest_pax` อยู่แล้ว แต่ฟอร์มยังไม่มีช่องกรอก)

เปลี่ยนเป็น 5 ช่องในแต่ละแถว:
```
[ชื่อ tier] [คนทั้งหมด] [จำนวนพระ] [ราคา] [×]
```
(แขก = total - monk คำนวณอัตโนมัติ ไม่ต้องกรอก)

### 2. สอน AI กฎใหม่ใน edge function (`supabase/functions/line-webhook/index.ts`)
เพิ่ม 2 กฎใน system prompt section ของ pricing:

```
กฎการตอบราคา:
- ถ้าจำนวนแขกตรงกับ tier → บอกราคา tier นั้น
- ถ้าจำนวนแขกอยู่ระหว่าง tier (เช่น 75 ระหว่าง 70-80) → ปัดขึ้น tier ถัดไป (80) แล้วบอกชัดๆ
  ตัวอย่าง: "75 ท่านแนะนำเป็นแพ็ก 80 ท่าน ราคา 34,000 ค่ะ (เผื่อแขกมาเกิน)"
- ถ้าเกินช่วงราคาสูงสุดของแพ็กเกจ → ห้ามเดาราคา ให้บอก "ขอส่งต่อทีมงานช่วยจัดให้นะคะ" + trigger SLA
```

### 3. เพิ่ม seed data
INSERT 4 แพ็กเกจใหม่ลง DB ผ่าน insert tool พร้อม:
- pricing_tiers (มี total_pax/monk_pax/price ครบ)
- custom_attributes (รายการที่ลูกค้าได้รับ — เช่น "พระสงฆ์: 9 รูป", "อาหารถวายพระ: เลือกได้ 3 เมนู")
- description (จุดเด่นวัตถุดิบของโต๊ะจีนแต่ละ tier)
- min_condition

### 4. ไม่แตะ schema
ไม่ต้อง migration — ฟิลด์ปัจจุบันรองรับครบหมด
